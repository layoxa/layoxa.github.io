The operating problem

Patient access breaks when the mobile experience, clinic dashboard, and practice system behave like separate products.

One stack. Three working surfaces.

The platform was designed so every patient action has a clear destination inside the clinic.

01

Patient apps

Native iOS and Android access for approved scheduling, communication, and patient workflows.

02

Clinic dashboard

Role-based queues and status visibility for front-desk and operating teams.

03

Practice integration

Production integrations for supported Open Dental and Dentrix workflows, with explicit read/write boundaries.

How a request moves

A specific example of the connected operating model.

01 · PatientRequests an appointment

The app captures intent and only the information needed for the workflow.

02 · RulesChecks valid capacity

Supported practice-system availability and clinic rules shape the options shown.

03 · ClinicReceives the action

Staff see the request, its status, and exceptions in a role-appropriate queue.

04 · SystemPreserves the source of truth

Approved changes return to the authoritative practice system with an audit trail.

Responsibility boundaries

Security and privacy are operating responsibilities. The implementation defines access, vendor agreements, subprocessors, retention, logging, consent, and the responsibilities of Leyoxa, the operator, and each practice.
